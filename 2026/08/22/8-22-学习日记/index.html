RAG 知识点补充

Dense Vector

Dense Vector 是稠密向量，一般由 Embedding 模型生成。它会把文本映射成一个高维连续向量，用来表示语义信息。

在 RAG 中，query 和文档 chunk 都会被编码成 dense vector，然后通过向量相似度召回语义接近的内容。它的优点是能处理同义表达和语义相似，但对精确编号、专有名词、代码、日期这类词面信号不一定敏感。

Sparse Vector

Sparse Vector 是稀疏向量，典型代表是 BM25、TF-IDF 这类关键词检索方法。它的维度通常对应词表，大多数维度为 0。

Sparse 检索更擅长精确匹配，比如错误码、函数名、术语、文档编号、人名、产品型号等。它和 dense retrieval 正好互补。

Embedding 训练和生成逻辑

Embedding 模型的目标，是让语义相近的文本在向量空间中距离更近，语义不相关的文本距离更远。

训练时通常会用成对或成组样本，比如 query 和相关文档作为正样本，不相关文档作为负样本，让模型学会把相关内容拉近、无关内容推远。

实际使用时，文档会先离线切成 chunk，再生成 embedding 存入向量库；用户 query 在线生成 embedding 后，与库中的 chunk vector 做相似度搜索。

Fusion 与 RRF

Fusion 指的是多路召回结果融合。比如同时做 dense retrieval 和 sparse retrieval，然后把两路候选合并成一个最终候选集。

RRF，也就是 Reciprocal Rank Fusion，是一种常见的融合方法。它不直接比较不同检索器的原始分数，而是根据候选在各路结果中的排名来加分。一个结果如果在多路召回中都排名靠前，最终融合分数就会更高。

这种方式适合 dense search、BM25、graph retrieval 等不同检索方式的融合，因为它避免了不同打分体系之间难以直接比较的问题。

Rerank

Rerank 是在初步召回之后，对候选结果进行二次排序。

第一阶段召回通常追求快和广，比如先召回 top-k；第二阶段 rerank 则更重视精度，会用 cross-encoder 或更强的模型重新判断 query 和候选文档的相关性。

在企业级 RAG 中，rerank 往往是提升回答质量的重要步骤，因为它能把真正适合放进上下文的 chunk 排到前面。

Qdrant

Qdrant 是一个向量数据库，用来存储 embedding vector、payload metadata 和原文相关信息，并支持向量检索、过滤和相似度搜索。

在 RAG 场景里，它可以用来保存文档 chunk 的向量，同时配合 metadata filter 做租户、权限、文档版本、时间范围等过滤。

ANN

ANN 是 Approximate Nearest Neighbor，也就是近似最近邻搜索。

真实场景下，向量数量很大，如果每次 query 都和所有向量暴力计算相似度，成本会非常高。ANN 的思路是牺牲一点点精确度，换取大幅度检索速度提升。

HNSW

HNSW 是一种常见的 ANN 算法，全称是 Hierarchical Navigable Small World。

它会构建多层图结构，高层用于快速跳转到大致区域，底层用于更精细地搜索邻近向量。可以理解成先快速接近目标区域，再在局部范围内细找。

很多向量数据库都会使用或支持 HNSW，因为它在召回效果和检索速度之间比较平衡。
