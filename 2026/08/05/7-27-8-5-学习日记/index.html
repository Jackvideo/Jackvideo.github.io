7.27-8.5 学习日记

学习情况

这段时间的学习内容比较散，但主线其实很清楚：继续围绕 Agent 工程往下走。

第一部分是 LangGraph 的基本概念和最小 MVP 实践；第二部分是继续看 Hello Agents 里的上下文工程、Agentic RL、MCP 连接方式，以及 Multica 这类产品里 Agent 注册和任务分发的实现思路；第三部分是刷链表题，重新体会了一遍 dummyHead 的重要性。

LangGraph：从图结构理解 Agent

这段时间先学习了 LangGraph 的基本概念，并动手做了一个最小 MVP。

之前看 Agent 工作流时，很容易只把它理解成“提示词 + 工具调用 + 大模型返回”。但 LangGraph 的视角更像是在写一个可控的状态机：

这样看之后，Agent 不再是一段松散的 prompt chain，而是一张显式的执行图。

最小 MVP 的核心其实不复杂：先定义一个共享状态，再写几个节点函数，让每个节点读取状态、修改状态，然后通过边把节点串起来。简单场景里可以是：

学完之后最大的感觉是：LangGraph 的重点不是“让 Agent 变得更玄学”，而是把 Agent 的执行过程变得更工程化。节点、状态和边都显式存在，后面做调试、重试、人工介入、多分支流程时会清楚很多。

上下文工程：Agent 能力的地基

Hello Agents 里关于上下文工程的部分也继续看了一些。

现在越来越感觉到，Agent 的能力上限不只是由模型本身决定的，还很大程度取决于上下文质量。所谓上下文工程，不只是“把 prompt 写好”，而是要系统地管理模型在当前任务中能看到什么、应该记住什么、需要检索什么、哪些信息应该被压缩或丢弃。

可以粗略理解成：

方向 关注点
指令上下文 任务目标、角色、约束、输出格式
会话上下文 当前对话、历史决策、用户偏好
工具上下文 可用工具、调用条件、工具返回结果
知识上下文 RAG 检索结果、引用来源、证据片段
长程记忆 可复用经验、项目背景、长期偏好

之前学习 RAG 时更关注“怎么检索知识”，现在看上下文工程，会发现检索只是其中一环。真正完整的 Agent 系统还要决定：什么时候检索、检索多少、怎么排序、怎么压缩、怎么放进上下文窗口，以及如何避免无关信息污染模型判断。

Agentic RL：刚开始打开的一扇门

Agentic RL 这块目前还只是开了个头。

先把 LLM 的训练过程重新捋了一遍：大体可以分成预训练和后训练。

如果放到 Agent 场景里看，强化学习的目标就不只是“回答更像人类偏好的答案”，还可能扩展到工具调用、任务规划、环境交互、错误恢复、多步执行等能力。

也就是说，Agentic RL 更关心的是：一个 Agent 在真实或模拟环境里，能不能通过反馈学会更稳定地完成任务。这里已经开始从“模型生成文本”走向“模型作为行动者”的视角了，后面值得继续深入。

MCP：从 SSE 到 Streamable HTTP

这段时间也顺带理解了一下 Agent 通信协议，尤其是 MCP 的连接方式。

MCP 可以理解成 Agent / Client 和外部工具、资源、Prompt 之间的一层标准协议。它让模型侧不需要为每个工具都写一套私有接入逻辑，而是通过统一的协议去发现和调用能力。

常见传输方式里，stdio 更适合本地工具：客户端把 MCP Server 当作子进程启动，通过标准输入输出交换 JSON-RPC 消息。它简单、直接，也很适合本地开发工具和命令行场景。

远程连接这块，我重点区分了一下旧版 HTTP + SSE 和新版 Streamable HTTP：

方式 特点
HTTP + SSE 旧版远程传输方式，一般需要一个 SSE 连接接收服务端消息，再用单独的 HTTP POST 端点发送客户端消息
Streamable HTTP 新版推荐的远程传输方式，使用统一 MCP endpoint，客户端通过 HTTP POST 发送 JSON-RPC，服务端可以返回普通 JSON，也可以用 text/event-stream 流式返回

所以 SSE 并不是完全消失了，而是从“旧版传输方案的核心形态”，变成了 Streamable HTTP 里可选的流式承载方式。

这个区别还挺关键：旧版 HTTP+SSE 更像是“长连接收消息 + 另一个端点发消息”；Streamable HTTP 则把接口形态统一到一个 MCP endpoint 上，同时支持普通请求响应、流式返回和服务端通知等形态。对远程 MCP Server 来说，新方式明显更利于工程化接入，也更方便后续接入网关、负载均衡、鉴权和观测系统。

Multica：Agent 注册与任务分发

还看了一点 Multica 这类产品的实现方式。

它比较有意思的一点是：任务协作层和 Agent 执行层是分开的。平台负责工作区、任务、Issue、分发、状态流转和协作记录；真正执行任务的是用户本机的 daemon 进程。

这种架构的好处是，平台可以像项目管理工具一样统一管理任务和协作，而执行环境仍然留在本地。对代码类 Agent 来说，这很合理：仓库、凭证、依赖、IDE、命令行工具很多时候本来就在开发者自己的机器上。

它让我意识到，企业级 Agent 产品不只是“套一个大模型聊天框”，更重要的是把 Agent 放进真实工作流里：谁能派活、谁来执行、执行环境在哪里、任务状态如何回传、失败后怎么重试、结果如何审计，这些才是产品化时绕不开的问题。

这批题做下来，最明显的感受是：链表题并不一定难在思路，而是难在指针操作的边界。

尤其是 dummyHead 真的很重要。它的价值不只是“写起来方便”，而是能统一头结点会变化的情况。比如合并两个有序链表、删除倒数第 N 个节点、两数相加、K 个一组翻转链表，这些题如果没有虚拟头节点，处理第一个节点时往往要写一堆特殊分支。

用了 dummyHead 之后，很多逻辑会更稳定：

链表题里还反复遇到几个高频模式：

模式 对应题型
快慢指针 环形链表、环形链表 II、回文链表、删除倒数第 N 个节点
双指针消除长度差 相交链表
原地反转 反转链表、回文链表后半段、K 个一组翻转
dummyHead 合并、删除、加法、局部翻转

K 个一组翻转链表尤其能暴露问题：每次反转前要先判断剩余节点够不够 K 个；反转时要保存 next，否则链表很容易断；反转完成后还要把上一段、当前段、下一段重新接起来。思路知道是一回事，指针能不能一次写对是另一回事。

阶段性总结

这十天左右学的东西有点多，但都在往同一个方向靠：怎么把大模型从“会回答问题”推进到“能在真实工程环境里完成任务”。

LangGraph 让我看到 Agent 执行过程可以被建模成图；上下文工程让我意识到信息组织本身就是核心能力；Agentic RL 把视角从文本生成推进到环境交互；MCP 和 Multica 则让我看到工具协议、运行时注册、任务分发这些更产品化、更工程化的部分。

算法题这边，链表专题也算重新打了一遍基础。接下来还是要继续练，尤其是指针题这种东西，真的不能只停留在“我脑子里懂了”，手上不熟就会出各种边界问题。

继续加油。
