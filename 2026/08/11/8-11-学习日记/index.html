学习情况

今天主要做了三件事：

  1. 以“面试 Agent”为练手项目，继续学习如何从 0 开始实践一个 Agent 应用；
  2. 看了一些 Pi Agent 相关解读，但说实话还没完全看明白；
  3. 刷了二叉树题目，重点练习 DFS 和递归，BFS 还需要继续补。

整体感受是：这段时间 Agent 理论确实看了不少，RAG、上下文工程、LangGraph、协议、产品架构都在脑子里转，但现在明显到了一个阶段：不能只继续读概念了，得靠项目和题目把它们压实。

面试 Agent：从概念走向 MVP

之前专门开了一条 Codex 会话，围绕“面试 Agent”这个练手项目做了路线设计。这个项目的定位很适合我现在的阶段：不需要一上来做一个特别大的平台，但它又天然包含 Agent 开发里很关键的能力。

这个 MVP 暂时不做网页、不做数据库、不做复盘 Agent，也先不急着用 LangChain / LangGraph。原因很简单：如果一开始就上框架，很容易变成“我会调用框架”，但不一定真正理解 Agent 背后的状态流转。

这一点对我很有提醒：第一阶段最该练的不是炫技，而是把 Agent 的最小骨架写清楚。

Agent 工程里真正要练的东西

这次路线里我觉得最关键的是职责拆分。

面试官 Agent 不应该直接等于“大模型聊天”。它至少要拆成几层：

模块 职责
models.py 定义面试配置、消息、状态、面试官决策
prompts.py 构造面试官系统提示词
llm.py / model_client.py 封装真实模型调用或 Fake 模型
agent.py / interviewer.py 控制面试流程和状态转换
main.py / cli.py 处理命令行输入输出
tests/ 用 Fake 模型验证状态机行为

其中最重要的是：业务状态必须由程序兜住，不能完全交给模型。

比如：

  • 未开始不能回答；
  • 面试已经结束后不能继续回答；
  • 空回答要拦截；
  • 最大轮数必须由程序强制控制；
  • 模型返回非法 JSON 时不能把脏数据写进会话；
  • 模型说要继续，但轮数到了，也必须结束。

这其实就是 Agent 工程和“单纯调 API 聊天”的区别。模型可以做语义判断，比如“该追问还是换题”；但程序要负责硬规则，比如状态、轮数、异常和数据一致性。

Pi Agent：理论需要实践来消化

今天也看了一些 Pi Agent 的解读，但说实话，看得不是很明白。

现在的问题不是完全没有概念，而是概念太多了：Agent、规划、工具调用、上下文、记忆、反思、环境反馈、强化学习、评测……每个词单独看好像都能理解一点，但合在一起就容易变成一团雾。

所以我现在的感觉是：不能继续只靠看理论往前推了。理论当然重要，但如果没有项目承接，很容易看完以后只剩下一些“高级名词”。下一步还是应该回到面试 Agent 这个练手项目里，把最小闭环跑起来。

阶段性总结

今天最大的感受是：学习 Agent 和刷算法其实有点像。

看 Agent 理论的时候，很容易觉得每个概念都懂一点，但真正落到代码里，状态怎么存、接口怎么拆、异常怎么处理、怎么测试，才是最考验理解的地方。

刷二叉树也是一样。中序遍历、最大深度、翻转二叉树看起来都不复杂，但真正要写稳，还是得把递归定义、终止条件和返回值想清楚。
